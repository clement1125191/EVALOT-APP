# Teacher first setup and assessment context

After sign-in, teachers without a completed educator profile see `/setup`. They answer one screen at a time: welcome, institution (optional logo/faculty/department), subject/course plus class/level pairs, optional additional institution, and a paper style. Formal/Clean/Compact cards render the teacher's real details. Common header commands and manual controls update the preview. Each institution has its own saved header configuration. The final screen confirms completion and offers preparation or dashboard. Saved progress resumes on later sign-in; completed onboarding is not repeated.

My Teaching lists institutions, assignments and header previews. Educators can add institutions, edit teaching details and choose a default. No education-level-specific tables or compulsory institution type are introduced. Subject and level remain paired; optional fields remain optional. Logos reuse the existing private upload/normalization service.

The shared context picker resolves unique assignments and asks for the institution, level or subject when multiple assignments remain. It does not silently guess a subject or cross institution boundaries. Manual and chat creation use the selected assignment. New assessments save a specification snapshot (institution, assignment, type, title, topics, duration, total marks, instructions and header) alongside the existing questions/marking scheme structure. Later profile edits do not modify existing assessment headers or specification snapshots.

Chat requests pass owned saved subject/level context to the current provider. Teachers review the assessment plan before question/marking-scheme generation. Requested duration and paper instructions are supported. Existing material-grounding, teacher consent, manual editing, preview, saving, setup completion and correction workflows continue to apply. New kinds: TEST, QUIZ, HOMEWORK, PRACTICE; EXAM, CAT, ASSIGNMENT and legacy ASSESSMENT remain. Homework/practice/assignment use simpler default instructions and omit student number by default.

Header customization currently handles common local commands: centre/left/right logo, remove student number, add candidate number, remove teacher name, make compact, department alignment. Other fields have manual controls. This command helper is not unrestricted AI layout editing. The broader reference's arbitrary AI document operations, enforcing source page ranges, pasting lesson content directly, deadlines, and DOCX export remain separate extensions; they are not implied by this onboarding increment. AI generation still requires the configured provider, consent and source materials; no live provider calls were made for these changes.

API: GET/PUT `/api/teaching/profile`; POST `/api/teaching/assessments`. Profile writes carry a revision. Inactive institutions/assignments are retained rather than deleting references used by past papers. Owner checks cover institution IDs, assignment IDs and logos. Educator events are append-only. Migration `010_educator_context.sql` is additive except extending the existing assessment-kind check. Existing assessments and correction publications are preserved.

Verification includes isolated PostgreSQL-compatible tests for resume/completion, optional fields, multiple institutions, stale revisions, duplicates, ownership, guide headers, all assessment types, context ambiguity, snapshots, chat context and immutable educator history. A native UI preview attempt was interrupted by browser/app access timing out; the new setup flow was not completed using real teacher data. Build and automated verification details are in VERIFICATION.md.

Each teaching assignment supports optional Department and Trade / Programme fields. The same subject and class can be assigned to different departments or trades; exact duplicates (ignoring case and surrounding spaces) are rejected. These details are saved in assessment context snapshots, displayed in preparation and library choices, and the assignment department overrides the institution department on newly created papers. Existing papers remain unchanged.
