# Phase 2 — assessment preparation
The teacher dashboard offers Exam, Assessment and CAT; metadata persists in PostgreSQL and old assessments remain Assessment by default. This scope was explicitly added by the user after correction-first Phase 1.

Workflow: create a draft with subject/class/total marks → upload materials → review the original → prepare manually or prompt AI → review questions and marking scheme → Save guide → Complete setup. The existing revision, readiness and immutable audit rules still apply. AI generation never writes directly into the saved guide.

Materials: PDF, JPG, PNG and UTF-8 TXT; actual byte validation, 10 MB/file, 50 pages/PDF, 25 MP/image, TXT up to 200 KB, maximum 5 files/30 MB per assessment, checksum deduplication. Originals live in a private database table and require owner authentication to retrieve. The viewer fetches authorized originals into temporary browser blob URLs; text renders as plain text. Uploads lock after setup. Existing assessment reference uploads and student scripts remain separate. Malware scanning remains an outstanding hosted-deployment safeguard.

AI: configure OPENAI_API_KEY and OPENAI_MODEL in ignored .env, then restart the API. Use a Responses-compatible model supporting PDFs, images and Structured Outputs. AI is unavailable when either setting is absent; manual preparation continues. User explicitly selects materials and consents to sending them to the AI provider. Only selected owned materials and the coverage request are submitted; no student scripts are used. store:false, two-minute timeout, 5 generations/teacher/15 minutes, max 30 questions, validated objective keys/essay rubrics/mark totals, source instructions treated as untrusted. Provider/validation errors leave questions unchanged. Generated questions, source IDs, prompt and model are retained in immutable generation history. Final guide changes use the existing teacher-owned audited Save guide action. External data retention follows provider policies; store:false is not a promise of zero retention. No live generation is claimed without provider configuration.

API: GET /api/preparation/options → {ai}; GET/POST /api/assessments/:id/materials; GET /api/assessments/:id/materials/:materialId/original; POST /api/assessments/:id/generate accepts {revision,prompt,count,materialIds,consent:true}, returns {questions,generationId}. All require teacher sessions, and writes use existing same-origin controls.

Dashboard preview: /design-preview.html is a development-only rendering of the same dashboard component, with explicitly labeled sample data; it makes no API calls and is excluded from the production entry. The real dashboard remains behind teacher login.

Official API references: [File inputs](https://developers.openai.com/api/docs/guides/file-inputs), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Preparation chatbot
Choose Exam, CAT, Assignment or Assessment when creating a paper. Upload learning notes and open Preparation settings: AI chatbot or Manual. AI mode accepts a prompt and question count, uses selected notes with consent, and returns a question/marking-scheme draft in conversation panels. Follow-up prompts carry the latest generated question set to the provider for revision. Click Use this draft in the question editor, check and edit it, then Save guide and Complete setup. Requests still require correct totals, valid answers and rubrics. Failed generation preserves saved questions and the earlier conversation.

Manual mode uses the same material review and question editor without sending notes to AI. The conversation is held while that paper is open; save the guide before navigating away. Generated drafts and prompts are retained in the existing generation audit records, but conversation restoration is not yet exposed in the interface. Assignment is enabled by migration 009_assignment_kind.sql.

## Preview beneath the preparation chat
Generated papers appear below the chatbot with Question paper and Marking scheme tabs. The student version omits expected answers and rubrics; the teacher version includes both. Edit paper copies the displayed version into the existing editor and scrolls there. The preview follows those edits. Save paper & scheme writes the displayed questions through the same revision-protected guide endpoint and updates the saved paper. Existing unsaved editor changes require confirmation before replacement.

Both tabs use the saved paper header/logo/footer; saving header changes updates the preview. Print opens an isolated document for the selected tab, so chat controls, other previews and the opposite document cannot print accidentally. Browser printing can save either document as PDF. A pop-up blocker or failed header load is reported. Saving a draft does not lock it; Complete setup remains a separate action. Saved question previews return when reopening the paper.

## Simple AI and manual dashboards
Exam preparation opens on a dashboard with Chat (AI) / Manually tabs, a prompt field, four actions and recent saved papers. New Assessment opens manual creation; Use AI Assistant opens AI creation; Upload Material carries the selected PDF/image/TXT into the new draft; Saved Papers opens the existing library. Paper details are confirmed once before creation and the prompt is carried into the AI conversation. No invented activities are shown.

Manually opens a three-step editor: Create Questions, Marking Scheme, Preview & Save. Assessment details are shown on the left, one selected question is edited in the centre, and question types/list are on the right. Add, duplicate, remove, MCQ options/answer selection, expected answers and rubrics use the existing question contracts. Notes and school layout are collapsed optional sections. Manual questions can be written without uploading notes. Saving keeps the draft editable; completing setup requires correct totals, guide coverage and saved layout/questions. Original teacher ownership, optimistic revisions and audits remain in force.

## Prompt-only AI setup
Choosing AI now opens a conversational workspace, not the metadata creation form. A teacher can start with a greeting. The assistant collects subject, class, paper type, total marks, question count and coverage over multiple replies, deriving only an optional title from confirmed details. Missing essential information or missing notes keeps the plan incomplete. The backend validates the structured plan before generation; a greeting never creates an assessment.

Notes are attached with + and sent for generation only with the existing note-sharing consent. Once the conversation is complete, the app creates the private draft, uploads notes and generates both question paper and marking scheme. Follow-up prompts revise it; preview, manual editing, save and print remain available. Existing-paper chats load teacher-owned saved context from the backend rather than asking for its details again. The metadata form remains only for manual creation.

Chat replies are rate-limited to 40 per teacher per 15 minutes. Generation retains its separate five-draft limit. Conversation text stays in the open workspace; save generated papers before leaving. The assistant and teacher still need to verify correctness. Gemini uses the configured backend key; no credentials are exposed in the browser.

## Dashboard and Marking simplification
AI conversations stay embedded below the preparation dashboard title. The + menu contains material uploads, saved papers and reusable school headers. Choosing a preferred header is saved per teacher in the library and reused for newly created papers; applying it never overwrites a paper header already edited. Recent Documents lists saved question papers, opens preview on the same dashboard, and omits empty setup drafts. Manual preparation retains its creation and AI-assistant actions.

Correction hub is labelled Marking. Create new marking offers a prepared Evalot paper or external paper/scheme uploads. Prepared papers with complete saved marking rules create a private session snapshot plus canonical PDF references automatically, with an immediately downloadable draft Excel workbook. This snapshot is preserved even if its source draft is edited later. The PDF reference renderer requires supported PDF font characters; papers with unsupported symbols require uploaded PDF references instead.

Workbook prompts support renaming, switching whole-class/individual capture, and adding an unconfirmed student (e.g. Add student Jane Doe reg S3-001). Commands are validated, revision checked, owner scoped and audited. They cannot assign marks or modify published workbooks. Student answers and final marks still require the teacher review workflow.
