# Reusable teaching materials and preparation setup

The preparation **+** opens a three-step native dialog: class and matching lesson, saved materials, ready-for-prompt summary. Institution/class choices come from My Teaching assignments; lesson options are restricted to that class. A single matching lesson is selected automatically. Saved papers, header library and manual preparation remain secondary actions.

**My library → Materials** organizes files as institution → class/level → subject/lesson. Uploads from the setup or library persist in the selected teaching folder, independently of assessments. Duplicate bytes in the same folder reuse the saved item; the same file in a different teaching assignment remains separately organized. Supported uploads: scanned PDF, JPG, PNG and UTF-8 TXT. Word `.doc/.docx` files are not supported in this increment; export them to PDF first. Limits: 10 MB/file (TXT 200 KB), 1,000 materials / 500 MB per teacher.

Teachers explicitly activate library use and select the files for the paper. Disabling activation retains the library files but excludes them from generation. Selected notes count as materials in preparation chat; no new upload is required. The existing provider consent checkbox is still required before AI receives the selected notes. Changing teaching context clears pending temporary uploads and resets provider consent. No whole-library access is implicitly granted.

When generation or manual creation starts, selected materials are copied to assessment-owned snapshots, deduplicated by content hash and audited with source library IDs. These snapshots preserve what the assessment used. Library source selection supports up to five documents / 30 MB per paper, matching the existing generation limits. A different source set that exceeds an existing draft's stored source limit requires a new draft. Completed assessment sources are locked.

Existing assessment notes can be saved into the matching folder from preparation setup using **Save this paper’s existing notes to the library**. Their original assessment copies remain unchanged. Notes are not silently assigned across institutions or unrelated subjects/classes. Previously uploaded assessment-only notes remain assessment-only until the teacher saves them to a teaching folder.

Migration `011_material_library.sql` adds `library_materials` and `library_material_uses`. Authenticated routes: GET `/api/library/materials`; POST `/api/library/assignments/:assignmentId/materials`; GET `/api/library/materials/:id/original`; POST `/api/library/assignments/:assignmentId/import-assessment`; POST `/api/assessments/:id/library-materials`. Activation returns only selected assessment snapshot IDs; generation uses those IDs rather than every stored document. All routes enforce owner and teaching-context checks. Uploads reuse byte-level validation; originals are private attachments.

Validation: 10 isolated integration tests cover persistence, exact originals, deduplication, cross-folder separation, spoof/size rejection, ownership, repeat activation, reuse across papers, source selection reaching the generation adapter, promoting existing notes, source limits and locking/audit history. No real teacher library or live AI provider was used for testing.
