# Correction hub, marks publishing and claims

Create a named correction workbook in **Correction hub**. Choose an existing completed paper, or enter subject, class and total marks for an external exam. Upload the question paper and marking guide as scanned PDF/JPG/PNG. External exams need confirmed structured questions/answers/rubrics before capture: enter the rules manually, or use optional AI transcription, review its draft and confirm. The confirmed guide is a private session snapshot; source references lock once correction starts.

**One student at a time:** choose Next student, open Scan lens or upload scans, save the front side first, then every remaining side in reading order. Confirm All pages saved, then Correct this student. Capture the next student while the background worker corrects the previous one. A laptop webcam is supported through browser camera permission; a phone can use a rear camera in a secure browser deployment. HTTPS/localhost is required for live camera access. Deployment outside localhost is not enabled by this project yet.

**Whole class:** capture separate student bundles or upload multiple PDFs, one complete PDF per student. Confirmed bundles wait until Correct all saved students. A single PDF containing several students is deliberately not automatically split: grouping must be verified by the teacher to prevent mixed identities. Partial upload failures retain already saved pages; finish the indicated bundle before publication.

The vision adapter reads student name/registration, transcribes handwriting, maps answers to source page numbers and suggests bounded marks using the confirmed guide. MCQ/True-False suggestions use local answer-key comparison after reliable transcription. Essays/short answers use rubric/marking notes with a rationale. Missing or unclear answers remain flagged; no final zero is assigned automatically. Confidence is a model estimate, not a calibrated probability. Red means error/uncertain draft, amber means capture/processing/review, green means teacher reviewed. Every student still requires teacher review.

Click a student to inspect original images/download PDFs, extracted text, question, guide, rationale and suggested mark. Edit transcription, identity or marks; check each review confirmation and save a reason. Names/registrations are never assumed final from OCR alone. Duplicate reviewed registration numbers are rejected. Appending a clearer recapture preserves earlier originals, archives the former draft in the audit history, resets the draft and requires page confirmation again.

**Marks publishing:** open the workbook, complete every review and resolve red flags, then Generate final published marks. Publishing is local to the teacher workspace; it does not send to students or CAMIS. Download true `.xlsx` or CSV, with draft/publication labels and numeric marks. Unreviewed AI suggestions can appear only in DRAFT exports. Publications and audit history are append-only snapshots. Formula-like CSV text is escaped; XLSX names/registrations are inline text cells.

**Claims:** choose a student and published version, record the concern, inspect the question/guide/originals and that version's correction draft. The student draft reopens for review. Save the teacher decision, resolve the claim with a reason, then publish a new version. Earlier published marks remain accessible and unchanged.

## Configuration and boundaries

The vision adapter is optional: set `OPENAI_API_KEY` and `OPENAI_VISION_MODEL` privately in `.env` and restart the backend. A Responses-compatible vision model must support images, PDF input and structured output. Without configuration, the UI allows capture/manual review and clearly disables AI correction/import. Explicit in-app consent is required before sending reference/student scans to the provider. No actual student data was sent during development. Implementation follows [official file input documentation](https://developers.openai.com/api/docs/guides/file-inputs).

Limits: 500 students/session, 500 MB/session, 10 MB/file, 50 pages/student; question/guide plus one student must be below 45 MB for AI. Guide import is limited to five drafts/15 minutes. A PostgreSQL queue and one local worker process one student at a time; uploads can continue concurrently. Jobs retain status/errors and interrupted jobs become retryable after five minutes. Provider requests time out after 120 seconds; second-level completion is not guaranteed and real handwriting accuracy/latency requires representative scans and a configured provider. This is a local development implementation, not a hosted classroom deployment.

Migration: `007_correction_hub.sql`. Routes under `/api/correction/sessions`: create/list/detail; question/guide uploads; setup-guide/import-guide; students/pages/complete/correct/manual/review; correct-all; publish; claims; exports. Sessions, files, marks, audits and claims remain teacher-owned with authenticated private access and same-origin write checks. Session/student revisions prevent stale reviews and publications. The queue keeps raw outputs and human overrides in the immutable assessment audit trail.

## Animated capture guide
The camera icon on Start scan lens opens a five-step animated route: front capture, save remaining sides, confirm the bundle, draft correction, teacher review. Pause/play, replay, direct step selection and back/next are supported. Start camera explicitly opens the live camera from the student guide. How capture works is also available on the Correction hub landing page and session panel. Native dialog focus/Escape handling and reduced-motion styling are provided. The tutorial is an illustration and does not capture a photo.
